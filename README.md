ЖерКөз («глаз на землю») — двусторонний сервис, связанный в реальном времени:

- **🗺 Веб-панель инспектора**: карта участков с цветовой индикацией статуса, карточка участка с фотофиксацией и контрольным сроком, жизненный цикл нарушения «Выявлено → В процессе устранения → Устранено / Возвращено государству».
- **🤖 Telegram-бот для жителей**: статус заявления по трек-номеру, база знаний по земельным услугам eGov и «Народный контроль» (геолокация → фото → описание).

**Замкнутый цикл:** житель отправляет сигнал в бот → точка сразу появляется на карте инспектора, участок желтеет → инспектор подтверждает нарушение → житель получает уведомление в Telegram.

Интерфейс и бот работают на двух языках: **қазақша** и **русский**.

## 🧩 Возможности

### Панель инспектора

| Функция | Как реализовано |
|---|---|
| **Карта участков** | Статус по картографическим правилам: 🟢 сплошная заливка, 🟡 пунктирный контур, 🔴 диагональная штриховка. Карту читают и люди с нарушением цветового зрения |
| Обзорный масштаб | Мелкие участки (ИЖС ~30 м) на общем плане показываются точками в цвете статуса |
| Подложки и слои | Схема (OpenStreetMap), спутник (Esri World Imagery), тепловая карта сигналов |
| **Жизненный цикл** | Пошаговый индикатор; нельзя, например, начать устранение без контрольного срока |
| Контрольный срок | Дата и быстрые кнопки +7 / +14 / +30 дней, счётчик просроченных (время Казахстана, UTC+5) |
| Фотофиксация | Загрузка с компьютера или камеры телефона, просмотр в полный размер; фото хранятся в БД |
| **Сигналы жителей** | Фото, описание, автопривязка к участку; «Взять в проверку / Подтвердить / Отклонить / Устранено» |
| **Объединение дублей** | Сообщения в радиусе 50 м за 7 дней собираются в один сигнал; уведомляются все сообщившие |
| **Подсказка типа** | Тип нарушения предлагается по описанию жителя (ключевые слова RU/KZ) и сразу подставляется в форму подтверждения |
| **🛰 NDVI Sentinel-2** | Индекс вегетации за год по реальным снимкам Sentinel-2 L2A (маска облаков, теней и снега) — кнопкой в карточке участка. Пакетное обновление ставит на проверку сельхозучастки без вегетации |
| **Маршрут выезда** | Просроченные нарушения, участки на проверке и сигналы в оптимальном порядке; открытие в Google или Яндекс Картах |
| **Акт осмотра** | Печатная форма A4: реквизиты, сигналы, фото, предписание, строки подписей → «Сохранить как PDF» |
| **Заявления** | Смена этапа с пояснением на RU/KZ; подписчики получают уведомление в Telegram |
| Реальное время | Server-Sent Events: новый сигнал появляется с пульсирующим маркером и уведомлением с фото |
| Дашборд | Счётчики, фильтры, поиск, экспорт реестра в CSV (открывается в Excel) |

### Telegram-бот

- **Без команд**: выбор языка при первом запуске, дальше всё на кнопках меню.
- **📄 Статус заявления**: понимает `KZ-2026-042`, `kz 2026 42`, `КЗ-2026-042` (кириллицей) и номер сигнала `SIG-0007` (точную точку видит только автор сигнала, остальные — район). Кнопка **🔔 Уведомлять об изменениях** включает подписку.
- **📚 База знаний**: изменение целевого назначения, продление аренды, участок под ИЖС. Сроки и документы сверены с паспортами услуг eGov.kz; у каждой процедуры прямая ссылка на услугу.
- **🚨 Народный контроль**: геолокация (кнопкой, через 📎 или текстом `42.90, 71.37`) → 1–3 фото (обычным фото или файлом JPG/PNG до 10 МБ) → описание → подтверждение. Бот сразу сообщает, на каком участке точка.
- **🗺 Карта района** (Telegram Mini App): сигналы рядом и «Мои сигналы». Публично видны только статус и тип нарушения, координаты округлены до ~10 м; жителя узнаём по подписи Telegram (`initData`, HMAC), без логинов.
- **Антиспам**: не больше 5 сигналов в час и 20 в сутки с одного аккаунта.
- **Уведомления**: о каждой смене статуса сигнала или этапа заявления, на языке жителя.

## 🏗 Архитектура

```
┌─────────────── один процесс Python ───────────────┐
│                                                    │
│  Telegram-бот (aiogram 3)     REST API + SSE       │      React + Leaflet
│  polling | webhook            (FastAPI)  ◄─────────┼────► панель инспектора
│        └──────────┬───────────────┘                │      и мини-приложение
│              services/  ← бизнес-правила           │
│              geo.py     ← вся геологика            │ ──► Copernicus (NDVI Sentinel-2)
│                   │                                │
└───────────────────┼────────────────────────────────┘
                    ▼
        PostgreSQL (геометрия в JSONB, фото в BYTEA)
```

- Бот и API работают с одним сервисным слоем, поэтому сигнал из бота мгновенно доходит до карты через шину событий и SSE.
- Бот не зависит от веба: сервисы уведомляют жителя через интерфейс `notify`, бот регистрирует свою реализацию при старте.
- Геометрия хранится как GeoJSON в JSONB, point-in-polygon считается в `services/geo.py` (shapely). Переход на PostGIS меняет только этот модуль.
- Спутниковые данные включаются ключами Copernicus в `.env`. Без них всё работает, NDVI показывается как симуляция с подписью.

**Стек:** Python 3.12 · FastAPI · SQLModel · psycopg 3 · PostgreSQL 16 · shapely · Pillow · aiogram 3 · pytest · React 18 · TypeScript · Vite · react-leaflet · leaflet.heat · Docker Compose · Caddy.

## 💻 Запуск локально

Нужно: **Python 3.11+**, **Node.js 18+**, **PostgreSQL 14+**.

**1. Бэкенд**

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
copy .env.example .env          # Linux / macOS: cp .env.example .env
```

В `backend/.env` обязателен только `DATABASE_URL`. По желанию: `BOT_TOKEN`, `INSPECTOR_PASSWORD`, `COPERNICUS_CLIENT_ID/SECRET` (все описаны в `.env.example`).

```bash
python -m app.db create              # создать базу и таблицы
python -m app.seed.generate --reset  # демо-данные: 31 участок, 10 заявлений, сигналы с фото
```

**2. Фронтенд**

```bash
cd frontend
npm install
npm run build
```

**3. Старт**

```bash
cd backend
python -m app.main
```

Откройте **http://localhost:8000**, документация API — http://localhost:8000/docs.

> Горячая перезагрузка фронтенда: `npm run dev` в `frontend` (http://localhost:5173, запросы проксируются на :8000).

> ⚠️ Не запускайте локальную версию с тем же `BOT_TOKEN`, что и на сервере: локальный polling снимет webhook, и облачный бот замолчит. Для разработки заведите тестового бота или оставьте `BOT_TOKEN` пустым.

**Тесты**

```bash
cd backend
pytest
```

84 теста на настоящем PostgreSQL (база `<имя>_test` создаётся автоматически): сквозной сценарий бота с подменённым Telegram, запросы к Copernicus с подменёнными ответами, переходы статусов, дубли, антиспам, мини-приложение, webhook.

## 🗂 Данные

Организаторы реальных данных не предоставляют, поэтому участки, заявления и сигналы симулируются. Спутниковые данные — настоящие.

- **Участки**: 31 полигон в Таразе и пригородах; 7 с нарушениями (3 просрочены), 5 на проверке, остальные без нарушений.
- **Сигналы**: 11 сигналов разных статусов плюс повторное сообщение о той же свалке (пример объединения дублей). У всех сигналов настоящие фотографии из Wikimedia Commons под свободными лицензиями, авторы указаны в [`ATTRIBUTION.md`](backend/app/seed/photos/ATTRIBUTION.md). Для уже заполненной базы: `python -m app.seed.real_photos`.
- **Трек-номера**: `KZ-2026-001`, `-007`, `-013`, `-018`, `-024`, `-029`, `-031`, `-036`, `-040`, `-042` — покрывают все этапы.
- **Спутник**: кнопка «🛰 Загрузить из Sentinel-2» в карточке участка или `python -m app.services.ndvi --limit 5 --flag` (ряды для 5 крупнейших участков, с/х участки без вегетации ставятся на проверку). Нужен бесплатный OAuth-клиент [Copernicus Data Space](https://dataspace.copernicus.eu).
- **Свои данные**: `python -m app.seed.import_geojson файл.geojson` (Polygon, MultiPolygon, Point; поля ищутся по вариантам имён).
- **Страховка для демо**: кнопка «⚡ Демо: сигнал жителя» или `python -m app.seed.simulate`.

## 📈 Масштабирование

| Направление | Уже сделано | Следующий шаг |
|---|---|---|
| Кадастр (ЕГКН, АИС ГЗК) | Импорт GeoJSON с сопоставлением полей и обновлением по кадастровому номеру | Регулярная синхронизация |
| Спутник | Рабочая интеграция с Copernicus Statistical API (Sentinel-2 L2A, маска SCL), автопостановка на проверку | Ночной пересчёт всех участков области |
| eGov | Сервис заявлений отделён от источника данных; база знаний ссылается на реальные услуги | Статусы заявлений напрямую из eGov |
| Геоданные | Вся геологика в одном модуле | PostGIS без изменений API |
| Нагрузка | Webhook, Redis для состояния диалогов бота | Redis Pub/Sub вместо внутренней шины событий |
| Доступ | Пароль инспектора, защита от перебора (на демо выключен) | Вход через ЭЦП, права по районам |
