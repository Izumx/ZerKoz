# ЖерКөз — цифровой мониторинг земель и сервис для граждан

Прототип (MVP) двустороннего сервиса для Жамбылской области, хакатон ZhambylHub.

- **Веб-панель инспектора**: карта участков с цветовой индикацией статуса, карточка участка с фотофиксацией, контрольными сроками и жизненным циклом нарушения «Выявлено → В процессе устранения → Устранено / Возвращено государству».
- **Telegram-бот для жителей**: статус заявления по трек-номеру, база знаний по земельным процедурам и «Народный контроль» (геолокация → фото → описание).

**Замкнутый цикл в реальном времени:** житель отправляет сигнал в бот → точка сразу появляется на карте инспектора, участок желтеет → инспектор подтверждает нарушение → житель получает уведомление в Telegram.

Интерфейс и бот на двух языках: қазақша и русский.

## Возможности

### Панель инспектора
| Функция | Как реализовано |
|---|---|
| Карта участков | Полигоны участков. Статус кодируется не только цветом, но и по картографическим правилам: 🟢 сплошная заливка, 🟡 пунктирный контур, 🔴 диагональная штриховка. Карту можно читать и при нарушениях цветового зрения |
| Обзорный масштаб | Мелкие участки (ИЖС ~30 м) на общем плане показываются точками в цвете статуса |
| Подложки | Схема (OpenStreetMap) и спутник (Esri World Imagery) |
| Карточка участка | Кадастровый номер, целевое назначение, площадь, землепользователь, открытые сигналы |
| Жизненный цикл | Пошаговый индикатор; допустимые переходы проверяются на сервере (например, нельзя начать устранение без контрольного срока) |
| Контрольный срок | Выбор даты и быстрые кнопки +7/+14/+30 дней, подсветка просрочки |
| Фотофиксация | Загрузка фото инспектором (в том числе с камеры телефона), просмотр фото жителей |
| Индекс вегетации | NDVI за 12 месяцев с подсказкой о возможном неиспользовании. Сейчас это симуляция, интерфейс готов к подключению Sentinel-2 |
| Сигналы жителей | Список, фото, описание; автоматическая привязка к участку (point-in-polygon); кнопки «Взять в проверку / Подтвердить / Отклонить / Устранено» |
| Реальное время | Server-Sent Events: новый сигнал появляется с пульсирующим маркером и всплывающим уведомлением |
| Дашборд | Счётчики нарушений, проверок, просрочек; фильтры; поиск; экспорт реестра в CSV (открывается в Excel) |
| История | Журнал всех изменений участка и связанных сигналов |

### Telegram-бот
- Выбор языка при первом запуске, дальше всё управляется кнопками меню, без команд.
- **📄 Статус заявления**: принимает `KZ-2026-042`, `kz 2026 42`, `КЗ-2026-042` (кириллицей), а также номер своего сигнала `SIG-0007`. Номер можно прислать и без нажатия кнопки.
- **📚 База знаний**: изменение целевого назначения, продление аренды, участок под ИЖС. Для каждой процедуры: шаги, документы, сроки и кнопка-ссылка на eGov.kz.
- **🚨 Народный контроль**: геолокация (кнопкой, через 📎 или текстом `42.90, 71.37`) → 1–3 фото → описание → подтверждение. Бот сразу сообщает, на каком участке находится точка.
- **Уведомления**: при каждой смене статуса сигнала инспектором житель получает сообщение на своём языке.

## Архитектура

```
┌─────────────── один процесс Python ───────────────┐
│                                                    │
│  Telegram-бот (aiogram 3)     REST API + SSE       │      React + Leaflet
│        │                      (FastAPI)  ◄─────────┼────► панель инспектора
│        └──────────┬───────────────┘                │
│              services/  ← бизнес-правила,          │
│              geo.py     ← вся геологика            │
│                   │                                │
└───────────────────┼────────────────────────────────┘
                    ▼
        PostgreSQL 16 (геометрия в JSONB)
```

- Бот и API работают с одним сервисным слоем. Поэтому сигнал из бота мгновенно доходит до карты через шину событий и SSE.
- Бот не зависит от веба: сервисы уведомляют жителя через интерфейс `notify`, а бот регистрирует свою реализацию при старте. Бот можно вынести в отдельный сервис без переписывания.
- Геометрия хранится как GeoJSON в JSONB, point-in-polygon считается в `services/geo.py` (shapely). Переход на PostGIS (`ST_Contains`, GiST-индекс) меняет только этот модуль.

**Стек:** Python 3.11+ · FastAPI · SQLModel · psycopg 3 · PostgreSQL 16 · shapely · Pillow · aiogram 3 · pytest · React 18 · TypeScript · Vite · react-leaflet.

## Запуск

Нужно: **Python 3.11+**, **Node.js 18+**, **PostgreSQL 14+**.

### 1. Бэкенд

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
copy .env.example .env          # Linux / macOS: cp .env.example .env
```

Откройте `backend/.env` и укажите:
- `DATABASE_URL`: подключение к PostgreSQL, например `postgresql+psycopg://postgres:ПАРОЛЬ@localhost:5432/zherkoz`;
- `BOT_TOKEN`: токен бота от [@BotFather](https://t.me/BotFather). Без токена запускается только веб-панель.

```bash
python -m app.db create              # создать базу и таблицы
python -m app.seed.generate --reset  # демо-данные: 31 участок, 10 заявлений, сигналы с фото
```

### 2. Фронтенд

```bash
cd frontend
npm install
npm run build
```

### 3. Старт

```bash
cd backend
python -m app.main
```

Откройте **http://localhost:8000**: панель, API и бот работают в одном процессе. Документация API: http://localhost:8000/docs.

> Разработка фронтенда с горячей перезагрузкой: `npm run dev` в папке `frontend` (http://localhost:5173, запросы проксируются на :8000).

### Тесты

```bash
cd backend
pytest
```

Тесты запускаются на настоящем PostgreSQL в отдельной базе `<имя>_test`, она создаётся автоматически.

## Демо-данные

Организаторы реальных данных не предоставляют, поэтому данные симулируются.

- **Участки**: 31 полигон в Таразе и пригородах (мкр. Жайлау, Карасу, ул. Толе би, промзона, Байзакский и Жамбылский районы). Из них 7 с нарушениями (3 просрочены), 5 на проверке, остальные без нарушений.
- **Тестовые трек-номера**: `KZ-2026-001`, `KZ-2026-007`, `KZ-2026-013`, `KZ-2026-018`, `KZ-2026-024`, `KZ-2026-029`, `KZ-2026-031`, `KZ-2026-036`, `KZ-2026-040`, `KZ-2026-042`. Они покрывают все этапы: на рассмотрении, назначен выезд, одобрено, отказ.
- **Страховка для демо**: кнопка «⚡ Демо: сигнал жителя» в панели или команда `python -m app.seed.simulate` создают сигнал с фото внутри случайного участка. Пригодится, если на защите недоступен Telegram.
- **Импорт своих данных**: `python -m app.seed.import_geojson файл.geojson`. Поддерживаются Polygon, MultiPolygon и Point; для точки строится квадрат по площади. Поля ищутся по вариантам имён (`cadastral_no`/`kad_nomer`/`кадастровый_номер`, `area_ha`/`площадь` …), существующие участки обновляются по кадастровому номеру.

## Масштабирование

| Направление | Что уже заложено |
|---|---|
| Государственный кадастр (ЕГКН, АИС ГЗК) | Импорт GeoJSON с сопоставлением полей и обновлением по кадастровому номеру; кадастровый номер служит единым ключом |
| Спутниковый мониторинг | Модель хранит ряд NDVI по участку; панель показывает тренд и признак неиспользования. Следующий шаг: регулярная загрузка индексов Sentinel-2 (Copernicus / Sentinel Hub) и автоматическая постановка участков «на проверку» |
| Геоданные | Вся геологика в одном модуле, переход на PostGIS без изменений API |
| eGov | Статусы заявлений читаются через сервис `applications`; его можно подключить к реальному источнику вместо тестовой таблицы |
| Нагрузка | Бот и API разделяются по модулям; SSE-шину можно заменить на Redis Pub/Sub |
| Доступ | Следующий этап: вход инспекторов через ЭЦП/IDP и разграничение прав по районам |
