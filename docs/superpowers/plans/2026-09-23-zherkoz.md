# ЖерКөз Implementation Plan

> **For agentic workers:** executed inline (superpowers:executing-plans style). Steps use checkbox (`- [ ]`) syntax for tracking. Full code lives in the repo; this plan fixes files, interfaces and verification commands.

**Goal:** MVP двустороннего сервиса мониторинга земель: веб-панель инспектора (карта, карточка участка, фото, дедлайны, жизненный цикл) + Telegram-бот для граждан (статус заявления, база знаний, «Народный контроль»), замкнутый цикл в реальном времени.

**Architecture:** Один Python-процесс: FastAPI (REST + SSE) и aiogram-бот (polling) в общем asyncio-loop; синхронный сервисный слой на SQLModel/PostgreSQL, который вызывают и API (threadpool), и бот (`asyncio.to_thread`). React SPA собирается Vite и раздаётся тем же FastAPI.

**Tech Stack:** Python 3.13, FastAPI, SQLModel, psycopg 3, PostgreSQL 16, shapely 2, Pillow, aiogram 3, pytest · React 18 + Vite + TS, react-leaflet 4, i18next.

## Global Constraints

- БД: PostgreSQL, геометрия — GeoJSON в JSONB, без PostGIS. Point-in-polygon только в `backend/app/services/geo.py`.
- Языки: RU + KZ в боте и в панели.
- Цвет участка вычисляется: red = lifecycle ∈ {detected, in_progress}; yellow = under_check или есть сигнал new|checking; иначе green.
- Переходы lifecycle: none→detected; detected→in_progress|resolved|returned; in_progress→resolved|returned; resolved|returned→detected. detected требует violation_type; in_progress требует deadline. Нарушение → HTTP 409.
- Переходы сигнала: new→checking|confirmed|rejected; checking→confirmed|rejected; confirmed→resolved; rejected→checking.
- Трек-номера: `KZ-2026-NNN`, сигналы `SIG-NNNN`.
- Сессии: `Session(engine, expire_on_commit=False)`.
- Сервисы коммитят сами и после коммита публикуют событие в `app.events.bus`.
- Фото: только изображения (проверка Pillow), ≤ 10 МБ.
